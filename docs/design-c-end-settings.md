# 设计：C 端「设置」页（与开发者模式分离）

> 状态：已与产品负责人收敛（2026-08）。术语定义见 [CONTEXT.md](../CONTEXT.md)。
> 本页不含 Code-behind 细节，只记录**为什么这么做**与**做什么**。

## 背景与目标

现有启动器把普通用户(小白)与开发者塞在同一套界面里：启动页一个「管理」按钮进完整管理界面，开发者向的敏感设置（本体目录、启动命令、网络镜像、Copilot 提示词）也都暴露在「启动器设置」面板中。新设计把两者分开：

- C 端在启动页上只看到一个「设置」入口，进去是**简洁的全屏页面**，能管好自己的版本、插件、技能和整合包，且随时能"打开各自的文件夹"。
- 开发者功能整体收归「开发者模式」，低调地待在新设置页角落与原有的「管理」界面里。

### 四个 tab 各自内容

- **DSH 版本**：当前使用版本、已装版本列表（切换「使用」/ 删除 / 打开 `.dsh-runtime/versions` 文件夹）、输入精确版本号下载新版本。复用「运行环境」页 DSH 面板的既有逻辑，**不暴露 Node.js 管理**（Node 是开发者事）。
- **插件**：已装插件列表 + 开关 + 打开插件所在 Profile 的 node_modules 文件夹。安装/卸载/排序不放进 C 端（引导走「开发者模式 → 资源市场」）。
- **技能**：技能列表 + 开关 + 打开 `~/.dsh/skills` 文件夹。获取更多技能引导走「开发者模式 → 资源市场」。顺带可放 **Agent 预设**（`~/.dsh/.agent-presets`，与技能同为独立目录的小资源，开关同样已有后端）——若产品判断预设偏开发者向，可仅放在开发者侧（标注为可反悔项）。
- **整合包**：已装整合包列表（当前启用高亮、可切换）、导入（选 zip → 预览 → 装入为独立 Profile）、导出（见 D7）、删除/打开包对应文件夹。省略 Profile 创建/克隆、仓库导入等开发者操作。

### 整合包（Pack）

| # | 决策 | 结论 |
|---|------|------|
| D7 | 导出内容 | 默认**声明式 + 本体尽量离线**：zip 带 manifest（name/description/version/dshVersion/plugins/skills/presets/applications）+ 插件本体 + 预设目录；**凭据、API Key、GitHub 登录态、代理配置默认不进包** |
| D8 | 导出选项 | 导出前弹**清单勾选**：DSH 版本(声明/可选含运行时本体)、插件、技能、预设、配置、密钥；默认只勾非敏感项 |
| D9 | 导入时 DSH 版本处理 | 整合包声明的 dshVersion **若本机未安装则自动下载并安装**该版本（现状只记录版本号、不补装——这是本轮唯一需要新增的后端行为） |
| D10 | 隔离语义 | 导入即**完整实例化**：自动生成 `pack-` 前缀独立 Profile，插件/配置互不干扰；启动页下拉仍可切换 |

### MCP

- **D11**：本轮**不做 MCP**。已核实本机 DSH（`~/.dsh`）没有 MCP 目录、`settings.yaml` 无 MCP 配置段。将来 DSH 支持 MCP 后，以"带开关的独立目录资源"形态（同插件/技能/预设）加入 C 端设置，入口位置预留即可，不预做 UI。

### Profile 的可见性

- **D12**：Profile 是隔离的真实载体（`~/.dsh/profiles/<名字>/`，含插件启用清单），但 **C 端不出现"Profile"这个词**。C 端只显示「当前使用：XX 整合包 / 默认配置」；原始切换能力保留在启动页既有的「启动配置」下拉。

## 新增/改动清单（给实现阶段的速览）

1. **前端**：新 `SettingsView`（C 端，全屏）：四个 tab + 左下角「开发者模式 →」链接；复用现有组件逻辑（版本列表、开关行、打开文件夹）。
2. **前端**：启动页 LauncherHome 右上角加齿轮「设置」按钮 → 打开新页面（surface）。
3. **后端（新增行为）**：导入整合包时，若 manifest 的 dshVersion 不在 `dshInstalled` 中 → 自动走 `installDshVersion(dshVersion)`，失败给出明确错误、不阻塞其余内容安装。
4. **后端（复用能力）**：导出清单勾选（含密钥选项）基于现有 pack 导出管线扩展入参；"命令/配置"类内容打包范围 = launchArgs/webPort/workspace/uiTheme/network（密钥默认排除）。
5. **不做**：MCP 管理、C 端不上 Node 管理/资源市场/Profile 创建克隆/仓库导入。

### 改版增补（2026-09-15 · 整合包前置 + 版本标识与推荐安装口径）

- **导航顺序**：整合包从末位提到「启动」右边第 2 位——整合包环境是这台启动器的核心对象（启动、版本、插件/技能/预设都围着它转），优先于其它面板。顺序单点定义在 `src/lib/nav.ts`，顶栏与 keep-mounted 渲染顺序同源（原来两处硬编码，改一处漏一处）。
- **版本标识**：可下载版本从「稳定版 / 预发布版」两组改为**按发布渠道归堆**（正式版 → rc → beta → alpha → 其它）。旧分组在上游从未发正式版的现实下恒为空组，等于没分组；渠道改从版本号本身解析，不再显示 npm dist-tag 裸词（此前 `0.1.5-rc.2` 因打了 `next` 标签而显示成 `next`，同版本串的 `rc` 对不上，用户分不清 alpha 与 rc）。版本行拆成「主版本号 + 渠道徽章」，渠道配色走主题语义变量（alpha 红 / beta 橙 / rc 蓝 / 正式版主蓝）。
- **推荐安装与检查更新统一口径**：由「读 npm `latest` 标签」改为「**稳定优先、同级取新**」（正式版 > rc > beta > alpha > 其它，同渠道取版本号最高）。上游至今没发正式版，`latest` 因此长期停在旧的 `0.1.5-rc.1` 上，导致首装与一键更新都落后于同渠道的 `rc.2`，而「检查更新」也读同一个标签、与安装路径各说各话。规则单点实现在 `electron/dsh-release.ts`，两条路径共用；「检查更新」的远端读取从 `/latest` 端点改为精简 packument（`application/vnd.npm.install-v1+json`）。
- **徽章口径**：「最新版」= 版本号最高者（可能是不稳定的渠道）；npm `latest` 改标「推荐安装」（名副其实：首装与一键更新装的就是它）。两者同版本时只显示「最新版」。

### 改版增补（2026-09-16 · 官方整合表 + 自动出包）

- **官方整合包改成「一个堆叠 + 版本列表」**：整合包页顶部一个折叠入口（合起来显示已下版本与「有新版本 X」，展开是各版本行：版本号 + `推荐` / `已下载` 徽标 + 适配 DSH + 发布时间 + 体积 + 下载按钮）。版本号 = 适配的 DSH 版本 + 序号，用户不用点开就知道适配哪个 DSH。重复下载同一版本得到「… (2)」副本（顺手修了中文显示名算不出序号后缀的老 bug）。
- **发现新版只提醒**：首装（本机无官方包）仍自动导入推荐版本；已有包则只在堆叠入口挂徽标。不静默拉几百 MB 是这次的核心取舍——官方包 100MB+，后台悄悄下载对用流量的用户不友好。
- **出包交给 CI**：判据只看 `@linxin666/dsh-web-all` 发版（officecli 单独发版不刷包），出包时把 officecli 升到当时最新；基线资产进仓库 `official-pack/`，本地 `npm run pack:official` 与 CI 共用同一脚本。每个包旁边多传一个 meta json 记录「这次用的 web-all / officecli / dsh」，既作下次判据也便于事后追溯。
- **导入即回原生外观**：外观重置从 `recommended-web-ui.ts` 抽成 `stock-appearance.ts` 并在官方包导入后调用（那条 UI 入口在 v0.1.1 就被移除了，函数一直没被复用）；状态取 `{ active: null, initialized: true }` —— `null` 是 skin-center 自己文档标注的 "stock look"，`initialized: true` 再堵一层 seed。
- **「适配 DSH」不许猜**：历史资产 `official-pack-v0.1.1.zip` 用的是旧命名（包版本 = 启动器版本，与 DSH 无关），它挂的 Release 正文是启动器更新日志、没有构建元信息，早期实现解析失败后拿包版本号冒充，于是界面上出现「适配 DSH 0.1.1」这种假信息（真机实际是 0.1.2-rc.1）。现在 DSH 版本只有两个可信来源：Release 正文的 `dsh:` 行、或新命名里编码的 DSH 版本（`0.1.5-rc.2.1` → `0.1.5-rc.2`）；两处都没有就返回 null，渲染层先用**本机已装这个包的真实绑定版本**补，仍补不上才显示「适配 DSH 未标注」。
- **下载有进度条、慢了自己换源**：整合包页在下载时显示百分比进度条 + 已下载/总量 + 实时速度 + 当前下载源。百 MB 级下载走 `electron/official-pack-download.ts`：候选链是「用户配置的镜像 → GitHub 直连 → 内置公共镜像」，三重守卫（等首字节 8 秒、断流 20 秒、5 秒窗口均速 < 300KB/s）任一命中就换源；所有源都慢时按实测速度挑最快的跑完，不再因慢反复换源。设置页的「GitHub 镜像」从裸文本框改成预设下拉，选「自动」即走上面这套。首页的品牌区与设置「关于」不再显示官方 QQ 群。
- **进度条要盖住「下载之后」**：用户反馈「100% 了怎么还没好」——下载完还要写盘、补装缺失的 DSH 运行时（约 100MB）、解压一万多个文件，这几段原先完全静默。现在同一条进度条按 `packProgress` 的 `stage` / `extract` 事件往下走（「正在准备 DSH x.y.z 依赖 · 64%」→「正在解压快照包… · 97%」），补装运行时的百分比由 `installProgress` 接力而来，没有百分比的阶段用不确定态动画并附一句说明。
