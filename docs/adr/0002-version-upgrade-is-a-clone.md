# 换 DSH 版本走「升版副本」，不原地改包

整合包记录自己引用的 DSH 版本，激活时把它对齐到全局运行指针。用户要把一个老包换到新版 DSH 时，我们决定**复制出一个新整合包**（预填名 `<原名> · DSH <新版本>`，可改），在新包里装目标版本，旧包原样保留、不劝删、仍可切回去用。

## Considered options

- **原地升级 + 备份回滚**：被否。聊天记录不可再生，而"升上去发现插件不能用"这种软失败没有退出码可判，备份回滚救不回来；留着旧包是唯一真正可靠的退路。
- 因为克隆本身就是退路，**升级前不再做任何快照/备份**。

## Consequences

不做兼容性预检：直接按目标版本装，装失败就**留着**那个副本（它多半启动不了），界面明说"这个包可能有问题"，并给一段可复制的修复提示词让用户交给 agent——与既有的失败引导（PCL2 式）路线一致。代价是包列表里会出现一对名字极像的包，靠命名里的版本标记消歧。

包内插件不自动升级；「这个插件适配哪个 DSH 版本」目前没有任何机器可读信号（只有 `resolveDshCoreOverrides` 在组合层缺版本时报错），所以我们不承诺"升完一定兼容"，也不给出一份需要我们自己长期维护的适配表。
