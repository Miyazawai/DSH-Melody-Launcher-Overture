# v1.0.3 — 装插件不再卡死整机 · web 包起得来 · 官方桌面端也管了

一句话版本：**这一版全是「修 + 补能力」，把三个 issue 关掉了，顺手把官方桌面端接了进来。整合包数据不用动，装 exe 覆盖就行。**

## 装完插件整机卡死（issue #12）

在 DSH Market 装 `dsh-web-all` 这种要拉一大棵依赖树的插件，Windows 会弹「没有响应」。卡顿不是安装本身造成的，是三处叠在一起：

- 安装输出是**逐条**送进界面的。pnpm 拉依赖时 stdout 每秒上百个 chunk，每个 chunk 触发两次状态更新。
- 插件页那半挂着**不分页**的精选目录，量级 3400+ 张卡片整表铺在同一个 DOM 里。于是每一次状态更新都要全量重渲染几千个节点，渲染线程连时间片都让不出来。
- 主进程每轮都用同步调用查系统代理，而且从不缓存。同步调用会把窗口消息泵直接冻住——那才是「整台电脑」跟着没响应的原因，不只是这个窗口。

现在：运行时输出按 120ms 合帧（一批只更新一次；相邻重复行去重、500 行上限、真实进程输出计数这些逐条语义都没变），市场列表分页每页 48 条，代理探测改成「同步读缓存 + 过期才在后台重探」。

同一条路上还补了两处小事：市场报错以前是一条没样式的裸行（那条 CSS 规则压根不存在）；从远端读回来的 npm 包名和版本以前不校验就拼进 `dsh plugin add` 的参数——Windows 上这条命令要走 `cmd.exe` 的批处理行，现在一律先过形状白名单。

## web 整合包一启动就退出，代码 1（issue #11）

日志长这样：`TypeError: credential ref "1" must match /^[A-Za-z_][A-Za-z0-9_]*$/`。

原因是凭据文件里有人的引用名填成了纯数字，或者干脆拿一条 URL 当名字用。DSH 的凭据插件因此拒绝激活，而 `connection`、`authorization`、`deepseek-account` 等十个插件全在等它，于是 DSH 报「1 required plugin did not activate」并以退出码 1 收场。修掉一个名字还会再冒出一条。

现在启动器在拉起 DSH 之前先把非法名字改成合法写法：数字名补一个前导下划线，符号折叠成大写标识符（`https://www.xxx.online` → `HTTPS_WWW_XXX_ONLINE`）。**密钥值一个字节都不动**，改的只有名字。三条约束钉住了：本来就合法的名字永不改写，撞名一律加 `_2`，所以反复启动是零改名、零新备份；改之前先备份原件，备份放在启动器自己的目录里（放在 DSH 家目录会被打进「可分享」的整合包导出）；落盘前自证改名后每个名字都合法、所有值的多集不变、会话记录那段逐字不变，做不到就不写。

改名结果和备份路径会同时进日志和启动失败诊断，弹窗里那条「复制给 AI 的提示词」于是自带撤销依据。

连带的另一条：以前这份文件里只要有一条非法名，整个解析就抛错，你在首页挂件里连 DeepSeek 的 Key 都存不进去。现在只把用不了的条目挡在外面，读写照常。

## 市场打不开也能装插件（issue #10）

插件页的「已安装」和「DSH Market」两个面板头各多了一枚**手动添加**：填 GitHub 仓库地址，或者填 npm 包名（可以带 `@版本`），直接让 DSH 按你填的来源装。它不查精选目录，也不调用 GitHub 的接口——市场页因为网络打不开的时候，这两点才是要紧的。

弹窗只有一个输入框，没有「来源」单选：两种写法的形状差得够远，多一个开关只是让你先做一遍本来不想做的判断。填 GitLab 之类会直说「只支持 GitHub 仓库链接」，不给一句含糊的「名称无效」。

市场自己那条耦合也松了一档：以前它动手之前先要联网拉一次精选目录，拉不到就报「目录为空或格式无效」，于是断网时连装一个你已经知道名字的插件都不行。现在先吃 30 分钟的磁盘缓存，只有冷启动没缓存才真的联网。

## 官方桌面端也管了

DeepSeek 在 09-29 发了官方桌面端。它和命令行共用同一个 DSH 数据目录，但它那份环境是它自己的——以前启动器对它只做「绝不写入」的躲避，这版加了一层显式管理：

- 插件页多了第三分段「**官方桌面端**」，整合包列表里也多了一行紧跟官方整合包的「官方桌面端」，写着它的版本、装了几个插件、是否在跑。
- 能列出它装了哪几个插件，能装、能卸。装卸**必须走它自己对外开的那条命令**，启动器绝不自己改它的清单。
- 一键让它走国内镜像：只改它自己配置里的 `registry` 一个键。第一次改动前把原件备份，随时「恢复原样」，换第二次镜像时备份仍是最初那份。不会把它的依赖池指到启动器目录——那等于把它以后所有安装的落点搬进我们家，它哪天重装就是一桩悬案。
- 一键打开桌面端应用。

**启用与停用做不了**：它对外提供的那条命令只支持安装与卸载，没有开关。我们替它改清单会和它自己的插件管理页对不上，所以行上没有开关，理由写在面板里，而不是等你找了半天才发现没这个按钮。开关请回桌面端自己的插件管理页。

顺带修掉一条真实的越权写入：以前只要装了桌面端，你在启动器里打开整合包页**看一眼**，它的配置文件就已经被我们补过了；一次性迁移还会把它的环境收编成一个普通整合包——一旦切过去，插件开关、市场安装、启动参数全部改朝桌面端自己的目录写。现在这四条路径一律跳过它。

这版只做到插件，桌面端的**配置**（模型、API 那些）还没接。

## 验证做到哪一步

- 自动化测试 861 → **933 条全过**，`tsc --noEmit` 与 `vite build` 干净。这一版新加 7 个测试文件共 58 例（代理探测 8、凭据改名 8 + 落盘 13、手动添加解析 5、桌面端发现 7 + 镜像配置 6 + 装卸服务 11），另外在凭据读写、安装链路、整合包迁移这些旧文件里各补了几例。
- 桌面端的**发现逻辑**在本机命令行实跑过一次：一次命中，版本与路径字段跟手工核对一致。它那条插件命令也在命令行跑过；「只支持安装与卸载、没有开关」这一点是从它打包好的源码里读出来的，不是凭 README 印象猜的。
- 界面那半是在浏览器里用演示数据点的：列表行位置、面板文案、镜像按钮从「设为」到「改为 / 恢复原样」、装一个插件后桌面端计数 2→3。
- **没做到的**：拿打好的 v1.0.3 exe 在真机上完整走一遍。所以 #12 那个卡顿本身我没法断言它没了——那一半得看装 `dsh-web-all` 的过程中窗口还能不能输入、搜索框打字跟不跟手，你试过请回来说一声。

## 你要做什么

装这个 exe 覆盖旧的就行，整合包数据不用动。

- **web 包起不来的**：直接点启动。日志里会出现一行说改了哪几个名字、备份在哪。不放心的话启动前先自己拷一份 `%USERPROFILE%\.dsh\.credentials.yaml`。
- **装了官方桌面端的**：去整合包列表那行点「管理插件」。它正在跑的话装完要重启桌面端才加载；配镜像同理。
- 便携版没有代码签名，SmartScreen 拦的时候确认来源是本仓库，再选「更多信息 → 仍要运行」。

## 已知问题：中文输入法会重复上屏

微软拼音在 DSH 网页输入框里选字，字或整句会重复一次。**这不是启动器改出来的**：现象在它自带的对话界面组件里，我把 0.1.7-rc.2 / 0.2.0-rc.1 / 0.2.0-rc.2 三个版本的这段实现对了，一字未改，所以**升 DSH 版本不解决**。可绕过的那一项是它内部的 composition 兼容模式开关，不是给用户的配置项，因此普通用户暂时没有办法绕过。写在这里是让你知道这锅在谁身上，我们正在准备上游 issue。
