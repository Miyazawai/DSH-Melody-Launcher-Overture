# v1.0.1 — 认出命令行部署的旧环境（下载问题请看 v1.0.2）

一句话版本：**这一版修好了整合包页的齿轮，也认得出你装启动器之前用 dsh 命令跑出来的那套环境；但它声称修掉的「下载卡在 82%」其实没修好，那条要到 v1.0.2 才真的解决。**

## ✨ 新增

- **认出命令行部署的旧环境**（[#9](https://github.com/Miyazawai/DSH-Melody-Launcher-Overture/issues/9)）：先自己 `npx @deepseek-ai/dsh web` 跑过、之后才装启动器的人，那个包以前只显示「DSH 未绑定 · 0 插件」，看着像原来那套配置和聊天记录作废了。现在它会挂一枚琥珀色的「命令行部署」徽标，鼠标停上去说明两件事：你的东西都在原处，以及这个包住在默认家目录、和其它同样没绑私有家目录的包共用一份数据。顶部那条「还没有绑定 DSH 版本」的提示也补了一句，说清绑版本不会动原来的配置和记录。

## 🐛 修复

- **下载 DSH 版本卡在 82% 然后抛「代码 1」**：这条链路上起的 pnpm 进程没带任何 registry 配置，只会按默认值去 `registry.npmjs.org`。插件安装、技能市场、pnpm 自身准备、DSH 子进程四处都设了镜像源和代理，唯独漏了这一处——偏偏它是唯一要拉整棵 DSH 依赖树的。现在它跟装插件共用同一份网络环境。
  > **这条没修好。** 发出去之后实测：pnpm 11 不读这里设的 `npm_config_registry` 环境变量，设了照样打官方源；而且真正的原因是那条命令上的 30 秒请求超时，跟用哪个源无关。v1.0.2 才是修好的那版，请下 v1.0.2。
- **整合包页每行末尾的齿轮点不动**：它自己带了禁用条件，所以只要有任何东西在跑（下载 DSH、装插件、启动服务），连展开操作条都不行——而展开只是改一个前端状态，不写任何东西。现在读条期间照样能展开看这个包有哪些操作，里面三个真正会写的按钮仍然禁用。

## 📦 下载

`DSH-Launcher-1.0.1-portable.exe`，单文件免安装。便携版没有代码签名，SmartScreen 拦的时候确认来源是本仓库，再选「更多信息 → 仍要运行」。
