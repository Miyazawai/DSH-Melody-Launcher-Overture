# v1.0.0 — 跨包搬运 · 数据格式护栏 · 启动器自身整理

一句话版本：**整合包之间终于能把聊天记录搬过去了，导出可以选择带走自己的密钥和会话，试新 DSH 版本走复制而不是就地改。剩下的大半是在填启动器自己的坑：并发写文件会写出坏数据、启动失败不告诉你死在哪、旧版本读不了新数据却还让你点。**

版本号从 0.1.3 直接跳到 1.0.0，是因为这一版之后功能面算闭合了：包能建、能搬、能整包送人，出事时启动器自己能说清楚问题在哪。没有什么大改版的意思。

## ✨ 新增

- **聊天记录跨包搬运**：整合包行多了「导入会话」，把另一个包的会话记录复制进本包，源包一条不少（只复制，不移动）。点下一步之前先看预览：能搬几条、多大、哪些搬不了以及为什么（工作目录已经不在了、记录格式比本包的 DSH 还新、引用的插件或预设这边没有）。搬完给一个撤销号，一键删掉这次复制进来的文件；哪条已经被 DSH 改过就留下哪条，并告诉你留了几条。

- **导出可以带走自己的东西**：导出弹窗多了两个勾选，「附带 API 密钥」和「附带会话记录」。默认都不勾，默认导出的包仍然不含任何私人数据，可以直接发人。勾了会先弹一层警告，说清这东西发出去收不回来，压缩包里也会多一份 `_PRIVATE-DO-NOT-SHARE.txt`。会话记录只在项目路径完全相同的那台电脑上看得见，换机器要先拷项目文件夹，这句就写在勾选下面。

- **切换版本等于复制一个新包**：想试另一个 DSH 版本，就复制一个新包去认它，当前包分毫未改，用不惯回原包继续用。本机没装的版本不再在弹窗里偷偷下 100MB——底栏按钮会换成「先下载 DSH x.y.z」，点了跳到 DSH版本页走那条有进度条的下载。

- **启动失败会告诉你死在哪一步**：DSH 起不来时弹的窗口分三种情况，端口不可用、进程没能拉起、运行中退出，每种给对应的原因行和该往哪边查。末尾附一段可以直接复制给 AI 的修复提示词，带上启动命令、工作目录、退出代码和原始输出。以前这些东西只滚在日志页里，刚上手的人分不清是端口被占还是缺运行库。

- **弹窗重做**：导出、导入会话、切换版本共用一套骨架，标题图标、右上角关闭、Esc 关闭、底栏按钮位置全部对齐。

## 🐛 修复

- **同时写同一个文件会写出坏数据**：启动器有 13 处「写临时文件再改名」的地方用的是固定文件名（`packs.json.tmp`）。两个写入者同时动手，后一个会接着前一个的尾巴往里拼，改名之后就是一份 JSON 里套了两份内容，读回来直接解析失败。现在统一走一个原子写实现，临时名带进程号和序号，改名撞 EPERM 时按 20/50/100/200 毫秒重试，进程崩溃留下的陈旧临时文件在下次写同一目录时收掉。

  这条在回归验证时还抓出我自己的一个错：兜底路径在改名失败时直接截断重写目标文件，而那正是并发读者读到撕裂 JSON 的原因。现在目标已存在就继续抛错，绝不截断。

- **DSH 升到 0.1.7 之后 0.1.5 起不来**：有用户这样反馈。查下来是 DSH 自己的规则——会话日志的存储格式只往上升（0.1.7 从 V3 升到 V4），旧版遇到新格式会拒绝解释，严重时在读目录阶段就抛错退出，端口根本没来得及监听。启动器此前有两处会主动制造这种组合：把新包的数据复制给更旧的版本，以及把新包的记录搬进更旧的包。现在两处都当场拦下并说明原因，切换版本的列表里也不再列更旧的版本。已经踩进去的用户，启动失败窗口认得 DSH 那几句英文拒绝，会换成人话。

- **npm 元数据改回官方源优先**：读包版本信息时先走镜像源，而镜像有复制延迟，结果是「提示可更新到 X，装下去却是 Y」。现在元数据走官方源，超时 10 秒才回落镜像。下载安装仍然镜像优先，那件事没变。

- **五个重复的 store 实例收成一个**：渲染层有五个组件各自 `useLauncherStore()`，各自一份状态。后果是看得见的：某些动作的转圈不亮、某些失败不弹提示、自动更新最多同时下三份。

- **DSH版本页满屏转圈**：点一个版本下载，列表里所有未安装的行都在转圈。进度事件里本来就带着版本号，改成只有对应那一行转。

- **导出和复制的弹窗点完就走**：这两个操作都要几分钟，弹窗自己又没有进度，还整块盖在页面正中，把顶部唯一那条真实进度挡得死死的。现在点完立刻关窗，结果交给一条提示。

- **夜间主题下原生控件看不清**：`select` 和 `input` 跟着系统画成白底黑框。补了 `color-scheme: dark`。

- **三个小缺陷**：官方包状态刷新的 `force` 参数在 preload 层被丢掉，「强制刷新」永远拿缓存；整合包迁移过程中有一个能读到半份注册表的竞态；网络失败时界面只显示 `fetch failed`，现在会带出真正的错误码（`ECONNRESET`、`ETIMEDOUT` 这类）。

## ⚡ 变更

- 删掉 817 行已核实的死代码：零引用的导出、七个早已跳过的 legacy 测试块、没人读的类型。
- 版本号比较与渠道解析统一收进 `src/lib/dsh-version.ts`，主进程和渲染层共用一份。
- 测试从 771 条增加到 857 条。

## 📦 下载

`DSH-Launcher-1.0.0-portable.exe`，单文件免安装。便携版没有代码签名，SmartScreen 拦的时候请确认来源是本仓库，再选「更多信息 → 仍要运行」。

## 备注

- **从 0.1.x 升上来的话，整合包、聊天记录、插件都不用重装**，直接覆盖运行即可。
- **官方整合包已经跟上 DSH 0.1.7**：`official-pack-v0.1.7-rc.1.1.zip`（适配 DSH `0.1.7-rc.1`、`@linxin666/dsh-web-all` 0.4.1、OfficeCLI v1.0.152，64MB / 3047 个文件）已挂到 Release。体积比上一包小了一半，原因在 web-all 0.4.1：它不再把 codemirror / lezer / iconify 那套前端依赖摊进包里的 `node_modules`，同时去掉了三个插件——`dsh-better-sidebar`、`@linxin666/dsh-doctor`、`@linxin666/dsh-tool-describe-image`。用旧官方包、依赖这三样的人重新下载官方包后就没有它们了，需要的话去插件页单独装。
- 已经装过旧版官方包的用户**不会**被动重下：新版本只提醒，由你决定何时下载。
- 反馈请开 [Issues](https://github.com/Miyazawai/DSH-Melody-Launcher-Overture/issues)，附上启动器版本和复现步骤。启动失败弹窗里那段提示词直接贴过来最好。
